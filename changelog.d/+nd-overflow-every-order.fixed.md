- An N-dimensional query returns `DistanceOverflow` exactly when a full scan of the distances it reads would, whatever the build order. `knn` with `k > 0` and `within` read the distance from the query to every point, and `pairs_within` and `dbscan` read every pair. The tree never prunes a subtree that may hold a point `2^510` or farther from the query. The build stores a distance that overflows as infinite instead of failing, so `VpTreeIndex::new` and `lc_nd_build` succeed or fail the same way for every order of the same points. `knn` with `k = 0` reads no distance.
