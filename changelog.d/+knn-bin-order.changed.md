The k-nearest walk visits sources in bin order and reads positions from slot-ordered copies, and each source writes its own output row, so a neighbour's shell is still in cache whatever order the caller's points come in. With the 262144-point cube shuffled, one thread takes 101 ms and eight take 23 ms, against 237 and 40 ms for 0.3.8; in the lattice's own order the times do not change.
